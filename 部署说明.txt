详细设计生成 Agent —— 离线迁移包（Qwen 实测用）
================================================

包内已包含全部 npm 依赖（node_modules）和已构建产物（packages/*/dist），
目标机器【不需要】 npm install、不需要上外网。

■ Node.js 运行时（已随包附带 node-v22.20.0-win-x64.zip）
  1. 解压 node-v22.20.0-win-x64.zip 到迁移包同一目录
  2. 不能配全局环境变量时，两种用法二选一：
     a) 双击【启动命令行.bat】——打开一个已临时配好 PATH 的命令行窗口，
        窗口内直接用 node 命令即可（关掉窗口不影响系统）
     b) 或用 node.exe 完整路径调用，例如：
        <解压目录>\node-v22.20.0-win-x64\node.exe packages\cli\dist\index.js ping
  3. 自检：node -v  应显示 v22.20.0
  （注意：不要用 Node v25.2.1，其 V8 正则引擎有 bug）

■ 部署步骤
  1. 把 lld-agent-迁移包.zip 解压到目标机器任意目录（路径含中文/空格均可）
  2. 编辑 lld.config.json：把 apiKey 的 REPLACE_WITH_REAL_KEY 改成真实 key
     （服务器开了 401 认证，key 向部署方索取；其余字段已配好：
      baseUrl http://10.0.75.130:4000，model qwen3.8-27b）
  3. 自检 CLI：
       node packages/cli/dist/index.js --help
  4. LLM 连通性自检：
       node packages/cli/dist/index.js ping

■ 流程图静态生成（2026-09-16 起，免 LLM）
  gen 的【流程图】步骤已不再调用 LLM——工具按 C 代码结构（tree-sitter AST →
  控制流图 → mermaid）确定性生成，节点标签就是代码原文（菱形=条件表达式、
  方框=语句）。一次调用必出图：完整控制流图 → 未识别构造降级为块 → 顺序链
  兜底，不再出现「有描述无流程图」；校验不过的图会按「CFG生成器缺陷」记入
  失败清单并自动用兜底图，不会静默缺图。
  - 只刷流程图完全离线、不需要 apiKey：
      node packages/cli/dist/index.js gen 测试模块/Gp_EcuStpStdn --out <产物目录> --only flowcharts
    （已有产物目录上加 --resume 可只补缺的图；描述/动态设计/配置说明等文字
     内容仍需 LLM，那些模式照常要 key）
  - 存量已验收的 LLM 流程图不受影响，只有重跑 gen --only flowcharts 的函数
    会被替换成静态生成图。
  - 生成后照常用 report + audit 出报告与渲染验收。

■ 流程图质量修订 + 状态机分图（2026-09-17 起）
  ① 条件编译虚线框归属修复：if/else 被 #endif 夹断的写法（else 体在 #if 区外），
     条件菱形现在正确画进所属虚线框（此前会漏到框外）。
  ② 局部变量定义不再进流程图（int x = 0 之类定义无流程语义），流程图只画
     赋值/调用/控制流等真实操作；for 循环初始化器不受影响照常显示。
  ③ 状态机图：多核模块按核角色分别绘制（主核 master/Core0 一张、从核
     satellite 一张，各成一个工作项，对齐序列图分图惯例）；触发条件改用
     语义化中文描述（不再只写裸函数名）。单核模块仍只画一张，无变化。
     ※ 09-17 晚补强（内网 v6 反馈「分了图但内容没变」后修复）：
     - 状态机 prompt 现在附带迁移驱动函数【完整源码】（此前只喂函数简介，
       模型看不到 satellite 自旋等待语句，画不出角色差异）；
     - 生成期新增内容硬校验：触发条件/note 必须含中文、多角色分图不得
       内容雷同，不合格自动打回重试（重试耗尽记入失败清单，不静默放行）。
  - 内网刷新既有产物的方法：
    a) 流程图（免 LLM）：
         node packages/cli/dist/index.js gen 测试模块/<模块> --out <产物目录> --only flowcharts --resume
    b) 状态机分图（需 LLM）：用文本编辑器打开产物目录的 lld_design.json，
       删掉 "stateMachine": {...} 整个字段（及 "stateMachines" 若有），然后：
         node packages/cli/dist/index.js gen 测试模块/<模块> --out <产物目录> --only dynamic --resume
       （--resume 会保留已有序列图，只重生状态机；触发条件裸函数名/英文、
        两角色图雷同等不合格内容会被硬校验自动打回重试，重试耗尽记入失败
        清单——生成后看失败清单里有没有 dynamic 条目即可，无需逐张目检）
    c) 照常 report + audit 出报告与验收。

■ 序列图静态生成（2026-09-21 起，免 LLM）
  gen 的【序列图】步骤已不再调用 LLM——与流程图同一套确定性路径（tree-sitter
  AST → 控制流图 → mermaid sequenceDiagram）：if/else→alt、else-if 链拉平、
  if 无 else→opt、while/for/自旋等待→loop、编译期 #if 区域→「宏 生效时/
  未生效时」opt/alt 包裹，消息=源码出现顺序的调用，标签一律代码原文
  （条件守卫是条件表达式原文，不再做中文润色）。
  - 多核角色分支（GetCoreId 返回值紧邻比较）自动分主核/从核两张图；
    两图内容无差异自动并回单图（如 IoM 的 GetCoreId 索引用法）。
  - 只画直接调用：跨模块被调函数在它自己的图里展开（与 v6 基准同口径）；
    空操作宏（NOP 类）除自旋等待体内外不画；条件里的调用（如
    if (CalloutChk() == FALSE)）会先发一条调用消息再进片段。
  - 任意函数必出图：控制流分析失败自动降级为按调用顺序的平铺图，不再
    出现序列图缺失或重试。
  - 内网刷新既有产物：用文本编辑器打开 lld_design.json，删掉
    "sequences": [...] 整个字段（改为 "sequences": []），然后：
      node packages/cli/dist/index.js gen 测试模块/<模块> --out <产物目录> --only dynamic --resume
    完全离线、不需要 apiKey（同一命令若同时缺状态机，状态机边标签润色
    仍会尝试调 LLM，Qwen 不可用时自动保持原文不中断）。
  - 存量已验收的 LLM 序列图（含 v6 手修基准）不受影响，只有删 sequences
    重跑的条目会被替换成静态生成图。

■ 缩写表定制（可选，两种提供方式）
  ① 外部人员提供 Word 缩写表：lld.config.json 加 "abbreviationsDoc": "项目缩写表.docx"
     （docx 内放两列表格：缩写|描述；「缩写」表进报告 3.1，「定义」表（表头 名称/定义|描述）
     进报告 3.2，均【全量收录表中全部条目】，与 Word 表保持一致；表头含「缩写」「定义/描述/含义」
     字样自动识别，无表头按前两列取，多表自动合并；路径相对运行目录）。
     配置后 3.1/3.2 以外部表为唯一来源（内建词典不兜底），report/audit 会打印
     「正文出现但外部表未定义」的缺口名单——把名单反馈维护方补 docx 即可。
  ② 模块特有/临时补充：lld.config.json 加
     "abbreviations": {"WWD": "Window Watchdog 窗口看门狗", ...}。
     两者同时在场：JSON 同名覆盖 docx 条目、新增补入；不配 docx 时 JSON 与内建
     29 条词典合并（原行为），report/audit 均生效。
     外部定义同时注入 gen：描述类生成（函数描述/配置说明/类型注释/外部接口说明/5.1）
     的 prompt 按出现过滤附带术语表（Spi_Setup 这类标识符分段也算 SPI 出现），
     术语口径与外部定义一致；流程图/序列图等结构生成不注入。

■ 常见问题
  - ping 报 401：apiKey 没改或不对。用 curl 独立验证 key：
      curl http://10.0.75.130:4000/v1/models -H "Authorization: Bearer 真实key"
  - ping 不通（超时）：先 curl http://10.0.75.130:4000/v1/models 确认网络可达
  - 模型 id 以 /v1/models 返回为准，若与 qwen3.8-27b 不一致，
    改 lld.config.json 的 model 字段与返回完全一致
  - Cannot find module '@lld/core'：node_modules/@lld 下的目录失效，
    正常情况下迁移包内是真实目录副本不会出此问题；若出现，检查该目录内容是否完整
