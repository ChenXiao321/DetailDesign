Modu.LLD 详细设计生成工具 —— 离线迁移包（内网部署用）
================================================

Modu 平台（MOdule Development Unit）第一阶段：C 代码 → ASPICE SWE.3 详细设计
HTML 评审报告。包内已包含全部 npm 依赖（node_modules）和已构建产物
（packages/*/dist），目标机器【不需要】 npm install、不需要上外网。

■ Node.js 运行时（不随包附带，需自备）
  迁移包不含 Node 运行时（体积原因），目标机器二选一：
  a) 机器已装 Node ≥ 18：直接使用（推荐 v22 LTS；
     注意：不要用 Node v25.2.1，其 V8 正则引擎有 bug）
  b) 不能装全局 Node：自行下载 Node 官网 Windows 免安装包
     node-v22.20.0-win-x64.zip，解压到迁移包同一目录，然后两种用法二选一：
     - 双击【启动命令行.bat】——打开一个已临时配好 PATH 的命令行窗口，
       窗口内直接用 node 命令即可（关掉窗口不影响系统）
     - 或用 node.exe 完整路径调用，例如：
       <解压目录>\node-v22.20.0-win-x64\node.exe packages\cli\dist\index.js ping
  自检：node -v  应显示 v22.20.0（或 ≥18 的其他版本）

■ 部署步骤
  1. 把 modu-迁移包-v<版本>-<提交号>.zip 解压到目标机器任意目录（路径含中文/空格均可）。
     文件名带版本与 git 提交号，包内根级【版本.txt】记录版本/提交/构建时间/条目数，
     出问题时把这两样报给维护方即可定位到确切代码。
     本包为部署精简版：不含示例模块源码与开发依赖，下文命令中的
     「测试模块/<模块名>」换成你的实际模块源码目录即可（产物目录任意指定）。
  2. 编辑 lld.config.json：把 apiKey 的 REPLACE_WITH_REAL_KEY 改成真实 key
     （服务器开了 401 认证，key 向部署方索取；其余字段已配好：
      baseUrl http://10.0.75.130:4000，model qwen3.8-27b）
  3. 自检 CLI：
       node packages/cli/dist/index.js --help
  4. LLM 连通性自检：
       node packages/cli/dist/index.js ping

■ 两个 bat 包装脚本的分工
  - 【lld-run.bat】干活的一键流程（自动化/工具集成入口）：非交互，带参数
    跑完 analyze→gen→report→audit 即退出，退出码 0/1/2 原样透传。
    Node 查找：PATH 里有 node 直接用；没有则自动探测包旁是否解压了
    node-v22.20.0-win-x64（有则本次运行自动补 PATH）；两者都无则报错退出 1。
  - 【启动命令行.bat】给人用的环境准备（机器没装全局 Node 时）：无参数，
    双击打开一个已临时配好便携 Node PATH 的 cmd 窗口，窗口内手动敲命令。
  - 无全局 Node 的机器上典型组合：先双击【启动命令行.bat】开好窗口，
    再在该窗口里调 lld-run.bat；外部工具直接 shell 调 lld-run.bat 时
    两种部署方式均可（全局 Node 或包旁便携 Node，bat 自动识别）。

■ 一键全流程（推荐，工具集成入口）
  node packages/cli/dist/index.js run 测试模块/<模块名> --out <产物目录>
  Windows 包装脚本（可被外部工具直接 shell 调用，退出码原样透传）：
    lld-run.bat <模块目录> <产物目录>
  一条命令串联 analyze → gen（增量续跑）→ report → audit：
  - 退出码：0=全绿；1=异常或结构完整性自检未过（残缺 json 不产出报告）；
    2=个别条目生成失败（报告已产出，原命令重跑即增量补齐）
  - 审计项（斜线/贴缘等设计内行为）不影响退出码，以 audit 打印的中文
    验收报告为准
  - 中断或退出码 2 后续跑：同一条命令原样重跑即可（gen 增量跳过已生成条目）
  - audit 需机器装有 Edge 或 Chrome 之一；不跑验收可用 node 命令加
    --skip-audit；--images 可在 report 前追加图 PNG 物化（见下文）

■ 分步执行（调试/精细控制用）
  # 静态分析（离线，不需要 apiKey）
  node packages/cli/dist/index.js analyze 测试模块/<模块名> --out <产物目录>
  # LLM 生成设计内容（增量落盘 lld_design.json，中断后原命令或加 --resume 续跑）
  node packages/cli/dist/index.js gen 测试模块/<模块名> --out <产物目录>
  # 出 HTML 评审报告（离线，不需要 apiKey）
  node packages/cli/dist/index.js report 测试模块/<模块名> --out <产物目录>
  # 渲染质量验收（离线；预渲染 SVG 成品版 lld_report.html + 斜线计数/交叉穿盒/
  # 箭头朝向审计，打印中文量化报告；需 Edge 或 Chrome）
  node packages/cli/dist/index.js audit 测试模块/<模块名> --out <产物目录>
  # 浏览器装在非默认路径时：set LLD_EDGE_PATH=<msedge.exe 或 chrome.exe 完整路径>

■ 报告骨架物化（document 节，2026-09-23 起）
  1/2/3/7/8 章正文、各章引导句、3.1/3.2 缩写定义表在 gen 期物化进
  lld_design.json 的 document 节，report/audit 纯渲染只读 json：
  - 缩写表 docx/JSON 更新后须重刷才反映到报告（确定性零 LLM，秒级）：
      node packages/cli/dist/index.js gen 测试模块/<模块名> --out <产物目录> --only document --resume
  - 存量 design json 无 document 节时 report/audit 回退旧行为（report 期现读
    配置，产物一致）并打印提示。

■ 图 PNG 物化（2026-09-23 起，归档/导出用，可选）
  把全部六类图（函数流程图/功能接口总图/内部函数调用图/状态机/序列图/
  4.2 包含关系图）渲染成 PNG（2x）以 base64 存回 lld_design.json：
      node packages/cli/dist/index.js gen 测试模块/<模块名> --out <产物目录> --only images --resume
  渲染走与报告完全一致的管线（内嵌 mermaid.js + 正交化后处理 + Edge 无头），
  免 LLM、需 Edge；--resume 跳过已有 PNG 的图，单图失败不中断可续跑补齐。
  HTML 报告渲染不变（仍由浏览器端 mermaid 实时渲染），PNG 为归档用途。

■ 流程图静态生成（2026-09-16 起，免 LLM）
  gen 的【流程图】步骤已不再调用 LLM——工具按 C 代码结构（tree-sitter AST →
  控制流图 → mermaid）确定性生成，节点标签就是代码原文（菱形=条件表达式、
  方框=语句）。一次调用必出图：完整控制流图 → 未识别构造降级为块 → 顺序链
  兜底，不再出现「有描述无流程图」；校验不过的图会按「CFG生成器缺陷」记入
  失败清单并自动用兜底图，不会静默缺图。
  - 只刷流程图完全离线、不需要 apiKey：
      node packages/cli/dist/index.js gen 测试模块/<模块名> --out <产物目录> --only flowcharts --resume
  - 存量已验收的 LLM 流程图不受影响，只有重跑 gen --only flowcharts 的函数
    会被替换成静态生成图。

■ 状态机（静态生成 + LLM 仅润色标签，2026-09-20 起）
  状态机图结构由 CFG 抽象解释确定性生成；LLM 只润色触发条件/状态描述
  （5.3.1.1 状态描述表 + 5.3.1.2 迁移说明，≤40 字中文，与标签润色同一次
  调用，不增加调用次数）。多核模块按核角色分图（主核/从核各一张）。
  LLM 不可用时自动保持原文不中断；图结构永远确定性、LLM 碰不到。
  - 内网刷新既有产物：用文本编辑器打开 lld_design.json，删掉
    "stateMachine": {...}（及 "stateMachines" 若有）整个字段，然后：
      node packages/cli/dist/index.js gen 测试模块/<模块名> --out <产物目录> --only dynamic --resume

■ 序列图静态生成（2026-09-21 起，免 LLM）
  gen 的【序列图】步骤已不再调用 LLM——与流程图同一套确定性路径：if/else→alt、
  else-if 链拉平、if 无 else→opt、while/for/自旋等待→loop、编译期 #if 区域→
  「宏 生效时/未生效时」opt/alt 包裹，消息=源码出现顺序的调用，标签一律
  代码原文。多核角色分支（GetCoreId 返回值紧邻比较）自动分主核/从核两张图，
  两图无差异自动并回单图；任意函数必出图（控制流分析失败降级为平铺图）。
  - 内网刷新既有产物：把 lld_design.json 的 "sequences": [...] 改为
    "sequences": []，然后：
      node packages/cli/dist/index.js gen 测试模块/<模块名> --out <产物目录> --only dynamic --resume
    完全离线、不需要 apiKey。

■ 缩写表定制（可选，两种提供方式）
  ① 外部人员提供 Word 缩写表：lld.config.json 加 "abbreviationsDoc": "项目缩写表.docx"
     （docx 内放两列表格：缩写|描述；「缩写」表进报告 3.1，「定义」表（表头 名称/定义|描述）
     进报告 3.2，均【全量收录表中全部条目】，与 Word 表保持一致；表头含「缩写」「定义/描述/含义」
     字样自动识别，无表头按前两列取，多表自动合并；路径相对运行目录）。
     配置后 3.1/3.2 以外部表为唯一来源（内建词典不兜底），report/audit 会打印
     「正文出现但外部表未定义」的缺口名单——把名单反馈维护方补 docx 即可。
     ※ 缩写表在 gen 期物化定型：更新 docx 后须重跑 --only document --resume
       （见上文「报告骨架物化」）才反映到报告。
  ② 模块特有/临时补充：lld.config.json 加
     "abbreviations": {"WWD": "Window Watchdog 窗口看门狗", ...}。
     两者同时在场：JSON 同名覆盖 docx 条目、新增补入；不配 docx 时 JSON 与内建
     29 条词典合并（原行为），report/audit 均生效。
     外部定义同时注入 gen：描述类生成（函数描述/配置说明/类型注释/外部接口说明/5.1）
     的 prompt 按出现过滤附带术语表（Spi_Setup 这类标识符分段也算 SPI 出现），
     术语口径与外部定义一致；流程图/序列图等结构生成不注入。

■ 常见问题
  - ping 报 401：apiKey 没改或不对。用 curl 独立验证 key：
      curl http://10.0.75.130:4000/v1/models -H "Authorization: Bearer 真实key"
  - ping 不通（超时）：先 curl http://10.0.75.130:4000/v1/models 确认网络可达
  - 模型 id 以 /v1/models 返回为准，若与 qwen3.8-27b 不一致，
    改 lld.config.json 的 model 字段与返回完全一致
  - Cannot find module '@lld/core'：node_modules/@lld 下的目录失效，
    正常情况下迁移包内是真实目录副本不会出此问题；若出现，检查该目录内容是否完整
